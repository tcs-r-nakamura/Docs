# 結果確認画面 パターン比較

以下に、AI-OCRで実際にあり得る
結果確認画面の構成案を複数提示します。

> 共通用語 (JobStatus / ReviewStatus / Provider / 対応ファイル形式 等) の
> 内部値と画面表記の対応は [用語集.md](用語集.md) を参照。

---

# 凡例

各セクションで使う見出しの意味:

- **必須情報**
  - 結果確認画面に存在する/載せるべき項目
- **関連実装(他画面)**
  - 結果確認画面外で既に実装されている関連機能(参考用)
- **将来要件**
  - 結果確認画面に追加する予定/検討中の機能
- **注意事項**
  - 実装上の制約・設計上の前提・既知の挙動など、画面利用時の留意点

# 結果確認画面に必要な画面情報

---

## 1. 処理済みファイル一覧(最重要)

### 必須情報

- ファイル名
- 処理日時
- ジョブステータスバッジ
  - `queued` / `running` / `succeeded` / `failed` / `canceled` を色分け
- レビュー状態バッジ
  - `未確認` / `完了` / `修正完了`
- 検索ボックス
  - ファイル名と ReportId で絞り込み
- フィルタパネル
  - ジョブステータス / レビュー状態 / 日付範囲(From/To)
  - 日付の自動入れ替え対応
  - フィルタ件数バッジで絞り込み状態を表示

### 将来要件

- OCR エンジンの表示
- 帳票種別の表示
  - テンプレート側に `category` フィールド追加が前提
- 信頼度低下件数(ジョブ単位の集計)
- 担当者の表示・絞り込み・割当
  - ユーザー識別の仕組みが現状なし
- 帳票種別フィルタ
- 低信頼度帳票の優先表示
- 大量履歴向けの仮想スクロール

---

## 2. 原本画像表示(中核)

### 必須情報

- PDF / 画像表示
  - `ImageDisplayViewModel` 経由で読み込み
- ページ切替
  - 前/次ボタン、`←` / `→` / `PageUp` / `PageDown` キー
- 拡大縮小
  - `Ctrl++` / `Ctrl+-` で 0.1〜5.0、ステップ 0.1
- バウンディングボックス表示
  - `ItemsControl` + Canvas オーバーレイで bbox を描画
  - 正規化座標を実座標に変換
- 選択項目ハイライト
  - テキストブロック ↔ bbox の双方向連動
  - bbox クリックで対応テキストブロックへスクロール
- 低信頼度強調
  - confidence 別の色分け
    - 高 (≥0.9): 緑 / 中 (≥0.7): 黄 / 低 (<0.7): 赤 / 不明: 青

### 将来要件

- 回転
- Fit Width / Fit Page の差別化
  - 現状は両コマンドとも `ZoomLevel=1.0` で実質同じ
- マルチ選択での領域比較
- 領域選択での手動再 OCR

---

## 3. OCR 結果編集エリア

### 必須情報

- テキストブロック表示(右ペイン ListBox)
- インライン編集
  - ダブルクリック / コンテキストメニュー「編集」で開始
  - Enter で確定、Esc でキャンセル
- 信頼度表示(パーセント形式)
- 編集マーカー(`*` HasChanges)
- Undo / Redo
- レビュー状態切替
  - 確認済み / 未確認に戻す
  - `CompletedWithEdit` のときは戻す前に確認ダイアログ
- 一括完了
  - 現ページの未確認ブロックをすべて確認済化
- 自動保存
  - レビュー状態変更時に API へ即時 PATCH
- 空白文字のみのバリデーション
- コンテキストメニュー
  - コピー / 編集 / 辞書に登録

### 関連実装(他画面)

- レビュー状態は `IReviewStateGatewayPort` 経由で永続化
- 辞書登録は辞書管理画面と連動

### 将来要件

- 項目名・ラベル表示
  - テキストブロックは現状「項目構造」を持たない(プレーンテキスト + bbox)
  - テンプレート連動で項目化する場合はモデル拡張が必要
- 必須項目表示
- 入力種別 (テキスト / 数値 / 日付 / 金額)
  - 種別ごとのバリデーション(Regex 等)も併せて検討
- 次の未確認へ移動 (ページ跨ぎのショートカット)
- 編集前後の差分表示
- 編集理由のメモ

---

## 4. ステータス管理

### 必須情報

- 文書(ジョブ)単位ステータス
  - **ジョブ実行ステータス**: `queued` / `running` / `succeeded` / `failed` / `canceled`
  - **レビュー状態**: `unreviewed` / `completed` / `completed_with_edit`
  - 一覧バッジで両者を別表示
- ブロック単位レビュー状態
  - `未確認` / `完了` / `修正完了`
- 一括完了
  - 現ページの未確認ブロックをまとめて確認済化
- 保存マーカー
  - `*` HasChanges、自動保存後にクリア

### 関連実装(他画面)

- レビュー状態は `IReviewStateGatewayPort` 経由でブロック単位に永続化
  - PATCH `/v1/jobs/{job_id}/review-state`
- ジョブ実行ステータスは OCR 実行画面のジョブ作成と共通

### 将来要件

- 「確認中」状態の追加 (`未確認` と `完了` の中間)
  - 現状は 2 値遷移のみ
- 承認 / 差戻しのワークフロー
  - レビュー状態に「承認待ち」「承認済み」を追加する設計
- 承認者の権限管理
  - ユーザー識別の仕組み(現状なし)とセットで設計

### 注意事項

- 文書単位の「エラー」は **ジョブ実行ステータスの `failed`** に対応
  - レビュー状態とは別軸で扱う
- レビュー状態の `completed_with_edit` は編集を伴う完了
  - 戻す操作には確認ダイアログを挟む

---

## 5. OCR 信頼度表示

### 必須情報

- 信頼度値の表示
  - 右ペインのテキストブロックにパーセント表示(`P0` フォーマット)
- 信頼度レベル分類
  - 高 (≥0.9) / 中 (≥0.7) / 低 (<0.7) / 不明
  - `Confidence` Value Object に集約(`OcrViewer.Sdk/Domain/ValueObjects/Confidence.cs`)
- bbox 色分け
  - 高: 緑 / 中: 黄 / 低: 赤 / 不明: 青
- ホバー時の TextLabel 表示
  - bbox 上にマウスを乗せるとテキストプレビューを表示

### 将来要件

- OCR 信頼度と抽出信頼度の区別
  - 現状は 1 値のみで、テンプレート抽出の信頼度は別途持たない
- 明示的な「要確認」警告バナー
  - 現状は色分けでのみ識別
- 画面側での confidence 閾値設定
  - 現状は VO 内のハードコード閾値(0.9 / 0.7)
- 低 confidence のみ絞り込み
  - 一覧の信頼度低下件数(セクション 1)と連動

### 注意事項

- ライン / テーブル単位の信頼度は持たない(`HasConfidence=false`)
  - 単語単位のみ confidence を保持
- 共通 `Confidence` VO で OCR 実行画面・テンプレート管理画面とも閾値を統一

---

## 6. テーブル認識結果

### 必須情報

- テーブル構造の取得
  - API から `NormalizedTable` / `NormalizedTableCell`(RowIndex / ColumnIndex / Text)
- テーブルのテキスト変換表示
  - `TableFormattingService.FormatAsText` で `[行,列] テキスト` 形式に整形
  - 例: `■ Table 1 (3×4)` ヘッダー + `[1,1] 日付` 等
- テーブル全体の編集
  - 1 つのテキストブロックとして編集
- Table bbox の画像オーバーレイ
  - `BoundingBoxType.Table` で表示
- 表示 ON/OFF トグル(`ShowTables`)

### 将来要件

- グリッドビュー形式の表組み表示
  - 現状はテキスト形式の縦並び
- セル単位の編集
  - 現状はテーブル全体を 1 ブロックとして編集
- 行 / 列の追加・削除
- セル結合 / 分割
  - テンプレート側に `row_span` / `col_span` 追加が必要
- 行のドラッグ並び替え
- 表構造の自動再認識

### 注意事項

- 請求書 OCR では明細部分の認識精度が業務影響に直結
- 現状の編集は 1 セルだけ修正でもテーブル全体のテキスト再入力扱いになる
  - 大規模テーブルの編集 UX 改善が課題

---

## 7. OCR 結果保存状態

### 必須情報

- 未保存マーカー
  - 右ペインのブロックに `*` HasChanges 表示
- 自動保存
  - レビュー状態変更時に API へ即時 PATCH
- 保存状態キャッシュ
  - `_reviewStateCache` で API 確定値を保持し、差分判定に使用
- 保存失敗時のロールバック
  - 失敗時は変更前の状態に戻し、ErrorMessage を表示
- 連続変更時の前回リクエスト自動キャンセル
  - `CancellationTokenSource` で 1 ブロックにつき 1 リクエストのみ進行

### 将来要件

- 最終更新時刻の UI 表示
  - 現状サーバー側で `updated_at` を保持しているが UI 未表示
- ブロック単位の「保存中...」インジケータ
  - 現状はアプリ全体の `IsLoading` のみで、保存中のブロック特定は不可

### 注意事項

- 大量修正時の保存漏れ事故防止のため、自動保存と未保存マーカーは必須
- 自動保存はレビュー状態変更が起点
  - テキスト編集のみ(`HasChanges`)では PATCH されない
  - 編集確定 + `CompletedWithEdit` への遷移で初めて保存される

---

## 8. エラー表示

### 必須情報

- エラーメッセージ表示
  - 画面下部に赤背景バナー(`ErrorMessage` バインド)
- Loading インジケータ
  - ProgressBar + 「読み込み中...」
- ジョブ失敗バッジ
  - 一覧で `failed` を赤表示
- API エラーキャッチ
  - 履歴読込 / 結果読込 / 保存の各操作で例外を捕捉
- 編集バリデーション
  - 空文字 / 空白文字のみは保存不可
- API リクエストバリデーション
  - `PatchReviewStateRequest` で `edited_text` と status の整合性チェック
    (例: `edited_text` は `CompletedWithEdit` のときのみ許可)

### 関連実装(他画面/共通基盤)

- 共通 `ErrorHandler` / `ErrorCategory`
  - 本画面では未活用、raw メッセージ表示のみ

### 将来要件

- カテゴリ別アイコン・色分け
  - 共通 `ErrorHandler` を経由した構造化表示
  - 認証 / 入力 / サーバー / タイムアウト等の区別
- 失敗箇所の bbox 強調
  - 認識失敗領域を画像上で視覚的に示す
- リトライ導線
  - ジョブ単位 / ブロック単位の再実行
- Timeout の専用処理
- 必須項目不足の表示
  - テキストブロックが項目構造を持たないため、テンプレート連動が前提

### 注意事項

- 現状の `ErrorMessage` は raw メッセージで、カテゴリ別の UI 分岐は無い
  - OCR 実行画面と同様、共通基盤未活用

---

## 9. レビュー導線

### 必須情報

- ページナビゲーション
  - 前/次ボタン
  - `←` / `→` / `PageUp` / `PageDown` キー
- 編集操作
  - `Enter` で編集確定 / `Esc` でキャンセル
  - Tab は WPF 標準のフォーカス移動
- ズーム操作
  - `Ctrl++` / `Ctrl+-` / `Ctrl+0` / `Ctrl+1`
- Undo / Redo
  - `Ctrl+Z` / `Ctrl+Shift+Z`
- 補助操作
  - `Ctrl+C` で選択テキストをコピー
  - `Esc` でフィルタパネルを閉じる
- 編集モードトグル
  - 未確認ブロックを TextBox 表示に切替
- 一括完了
  - 現ページの未確認ブロックをまとめて確認済化

### 関連実装(他画面/共通基盤)

- ヘルプパネル(`HelpPanelViewModel`)で全画面のショートカット一覧を表示
  - 結果画面のショートカットも掲載済み(`HelpPanelViewModel.cs:124-131`)

### 将来要件

- ページ跨ぎの「次の未確認へ」専用ナビ
  - 現状は同ページ内の編集モード切替のみ
- Enter 連打での連続レビュー
  - 確認 → 次のブロックへ自動フォーカス
- 自動レビュー
  - 高 confidence ブロックの自動確認済化
  - confidence 閾値の画面側設定(セクション 5 と連動)

### 注意事項

- 大量修正業務ではキーボード操作の充実度がそのまま処理速度に直結

---

## 10. 履歴・監査

### 必須情報

- 編集履歴の内部保持
  - `TextEditingViewModel.EditHistory` で `UndoRedoService` 経由の編集スタック
- Undo / Redo
  - `Ctrl+Z` / `Ctrl+Shift+Z`、ボタン Tooltip に次操作を表示
- サーバー側の更新追跡
  - `updated_at` と `edited_text` を永続化

### 将来要件

- 編集履歴の UI 表示
  - タイムライン / 一覧で過去の修正を可視化
  - 現状は内部スタックのみで、ユーザーから見えない
- 編集者の記録
  - ユーザー識別の仕組みが現状なし
  - 認証基盤とセットで設計が必要
- 修正前後の差分ビュー
- ブロック単位の最終更新時刻表示
  - サーバーは保持済、UI 未表示
- 監査ログのエクスポート
- 変更履歴のロールバック
  - 過去の編集に戻す UI
  - サーバー側に履歴スナップショットを保持する設計が前提

### 注意事項

- 現状の Undo / Redo は **セッション内のみ** で、アプリ再起動後は失われる
- ロールバック実装にはサーバー側に履歴スナップショット保存機構が必要

# 結果確認画面の代表的な画面分割

現在の実装状況・将来要件・AI-OCR 製品の実例を踏まえ、
結果確認画面のレイアウト案を以下の 2 パターンで整理する。

- **将来設計なし版**(現実装寄り) … パターン①
- **将来設計あり版**(AI-OCR 完成系寄り) … パターン②

結果確認画面は AI-OCR において最も重要な画面であり、

```text
「OCR結果を見る画面」
```

ではなく、

```text
「OCR結果を確認・修正・承認・管理する画面」
```

として設計する必要がある。

---

## 前提整理

現在の設計は、左:履歴一覧 / 中央:原本 + bbox / 右:編集 の責務分離が非常に綺麗。

| 方針 | 評価 |
| ---- | -- |
| 左:処理履歴一覧 | ◎ |
| 中央:原本画像 + bbox | ◎ |
| 右:OCR 結果編集 | ◎ |
| confidence 色分け | ◎ |
| レビュー状態の永続化 | ◎ |
| キーボードショートカット | ◎ |

---

# 将来設計なし版(現実装ベース)

---

## パターン① シンプル3ペイン型(最推奨)

現在の構成を実装ベースで強化。レビュー状態管理 (`review_status`) と
フィルタ・コンテキストメニュー・QuickDictionaryPanel オーバーレイを含む現実装の責務を網羅。

### 画面図

```text
┌──────────────────┬────────────────────────┬──────────────────────┐
│ ジョブ履歴       │ 原本画像 + bbox         │ 抽出テキスト         │
│ [🔍 検索...]     │                         │              ✎📑↶↷⟳ │
│ ▼ フィルタ(2)    │                         │                      │
│ ──────────       │  ┌──────────────────┐  │ ──────────────────── │
│ invoice.pdf      │  │ bbox (緑=高/黄=中/│  │ 株式会社○○ *        │
│  [✓成功][修正完] │  │      赤=低/青=不明)│  │  信頼度 95% ☑完了    │
│  2025/05/21 12:34│  │                   │  │  [確認済み][未確認↩] │
│  └rep:abc...     │  │  ←双方向連動→    │  │ ──────────────────── │
│ order.pdf        │  └──────────────────┘  │ ¥12,300              │
│  [✓成功][未確認] │                         │  信頼度 72% ☐未確認  │
│  2025/05/21 11:20│  ＜ ページ 1/3 ＞       │  右クリック:         │
│ receipt.pdf      │                         │   ・コピー           │
│  [✗失敗][未確認] │                         │   ・編集             │
│  2025/05/21 09:15│                         │   ・辞書に登録...    │
└──────────────────┴────────────────────────┴──────────────────────┘
                    [QuickDictionaryPanel: 右クリック「辞書に登録」で
                     スライドインオーバーレイ表示]

凡例:
  左ペイン:
    🔍 = 検索ボックス (ファイル名 + ReportId 絞り込み)
    ▼ フィルタ(N) = フィルタパネルを開く + 適用件数バッジ
       (ジョブステータス / 確認ステータス / 日付範囲)
    [✓成功]/[✗失敗] = ジョブステータスバッジ (queued/running/succeeded/failed/canceled)
    [未確認]/[完了]/[修正完了] = レビュー状態バッジ (ReviewStatusBadgeDisplay)
    空状態:
      履歴なし → 「履歴がありません」
      フィルタ結果0件 → 「条件に一致する履歴がありません」

  中央ペイン:
    bbox 色分け: 緑=高(≥0.9) / 黄=中(≥0.7) / 赤=低(<0.7) / 青=不明
    bbox ↔ テキストブロック双方向連動 (クリックで対応箇所にハイライト・スクロール)
    ホバーで bbox 上にテキストラベル表示
    空状態: 「結果が読み込まれていません」
    画面下部にページナビゲーション (◀ ▶ + ページ N/M、キーボード ←/→ も可)

  右ペイン:
    ✎ = 編集モードトグル (確認ステータスの編集を有効化)
    📑 = 一括完了 (現ページの未確認ブロックをすべて確認済化、編集モード時のみ)
    ↶ ↷ = Undo / Redo (Tooltip に次操作の説明表示)
    ⟳ = リセット (全編集を元に戻す、編集ありの時のみ)
    * = 編集マーカー (HasChanges)
    ☑/☐ = レビュー状態 (完了/未確認)
    [確認済み][未確認↩] = レビュー状態切替ボタン
      ※ CompletedWithEdit → Unreviewed は確認ダイアログを挟む
    インライン編集: ダブルクリック / コンテキストメニュー「編集」で開始、
      Enter で確定・Esc でキャンセル、✓/✕ ボタンも併設
    コンテキストメニュー (右クリック): コピー / 編集 / 辞書に登録...

  📌 保存タイミング (現実装):
    テキスト編集 (Enter 確定) → `CommitEdit()` (TextBlockViewModel.cs:134)
      初回編集 (Unreviewed/Completed): ReviewStatus → CompletedWithEdit に遷移 → PATCH
      再編集 (CompletedWithEdit): ReviewStatus は変わらず、Text 変更を契機に PATCH
                                  (ResultViewModel.cs:1028)
    レビュー状態変更 (☑/[確認済み])  → API へ即時 PATCH (自動保存)
    ↶/↷/⟳ (Undo/Redo/リセット)     → Text/ReviewStatus 変更条件次第で PATCH 発火
    ※ Enter 確定で必ずサーバー保存される設計

  表示フィルタ (Words/Lines/Tables):
    bbox の表示種別を切替 (`ShowWords` / `ShowLines` / `ShowTables`)

  オーバーレイ:
    QuickDictionaryPanel = 右クリック「辞書に登録」で右側スライドイン
```

### 自動保存・連続編集の動作

- レビュー状態変更時に **API へ即時 PATCH** (`PATCH /v1/jobs/{job_id}/review-state`)
- **保存状態キャッシュ** (`_reviewStateCache`) で API 確定値を保持、差分判定に使用
- **失敗時はロールバック** (変更前の状態に戻し、ErrorMessage を表示)
- **連続変更時は前回リクエスト自動キャンセル** (`CancellationTokenSource` で 1 ブロックにつき 1 リクエストのみ進行)

# 一押しのパターン

## 短期 (即時実装) → パターン① シンプル3ペイン型(最推奨)

### 理由

- **現実装の構造そのまま**、改修コスト最小
- レビュー作業の本命構成: **画像+bbox を見ながらテキスト編集** を同時に行える
- 直近実装の **`review_status` 機能 (レビューバッジ/フィルタ/一括完了)** を完全反映
- **bbox ↔ テキストブロック双方向連動** が画面内で完結 (3ペインの真骨頂)
- confidence 別 bbox 色分け (緑/黄/赤/青) で要確認領域を視覚的に把握
- 検索 + フィルタパネル (ジョブステータス + 確認ステータス + 日付範囲) で履歴の絞り込みが効率的
- QuickDictionaryPanel オーバーレイで辞書登録が即座可能
- 17/17 責務完全カバー

### 学習コスト最小

WPF のクラシックな Master-Detail (3-pane) 構造で、左から右への自然な操作フロー (履歴選択 → 画像/bbox 確認 → テキスト編集) を保証。
