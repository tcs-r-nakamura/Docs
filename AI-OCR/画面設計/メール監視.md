# メール監視画面 パターン比較

以下に、AI-OCRで実際にあり得る
メール監視画面の構成案を複数提示します。

---

# 凡例

各セクションで使う見出しの意味:

- **必須情報**
  - メール監視画面に存在する/載せるべき項目
- **関連実装(他画面)**
  - メール監視画面外で既に実装されている関連機能(参考用)
- **将来要件**
  - メール監視画面に追加する予定/検討中の機能
- **注意事項**
  - 実装上の制約・設計上の前提・既知の挙動など、画面利用時の留意点

---

# メール監視画面に必要な画面情報

メール監視は単なる「メール受信」ではなく、自動 OCR ワークフロー(仕分け 〜 OCR 投入 〜 結果保存)の起点となる画面である。

```text
メール受信
↓
添付取得
↓
OCRエンジン判定
↓
テンプレ選択
↓
OCR実行
↓
結果保存
```

---

## 1. メールアカウント管理

### 必須情報

- アカウント追加・編集・削除
- メールサーバー(IMAP / Exchange / Gmail 等)
- 認証情報(ユーザー / パスワード / OAuth)
- アカウント別の有効/無効

### 将来要件

- アカウント別の取得頻度設定
- アカウント別の保留メール上限

### 注意事項

- 認証情報は安全な保管(OS キーチェーン / シークレット管理)が必須

---

## 2. ルール一覧(最重要)

### 必須情報

- ルール名 / 有効フラグ
- 送信者パターン(`*@invoice.com` など)
- 件名条件
- 添付条件(拡張子 / サイズ)
- 適用 OCR Provider / Engine
- 適用テンプレート
- 優先度

### 将来要件

- ルールの並べ替え(優先度ドラッグ)
- ルール複製・テンプレート化

---

## 3. ルール詳細編集

### 必須情報

- 上記の各フィールドの編集 UI
- 保存・キャンセル
- バリデーション(Regex 構文・必須項目)

### 将来要件

- IF...THEN 形式の条件ビルダー(複雑条件)
- ルール適用前後の差分プレビュー

---

## 4. 接続状態

### 必須情報

- アカウント別の接続ステータス(接続中 / Error / Polling)
- 直近のポーリング時刻
- 直近のエラー内容

### 将来要件

- 接続失敗時の自動リトライ
- アラート通知(メール / Webhook)

---

## 5. テスト受信

### 将来要件

- 「テストメール取得」ボタン
- ルール適用結果のドライラン表示

### 注意事項

- 本番運用前にルール検証する手段がないと、誤判定で OCR コストが膨らむため必須化したい

---

## 6. 処理履歴

### 必須情報

- 受信メール一覧
- 適用ルール / OCR 結果リンク
- 処理ステータス(受信 / OCR 中 / 完了 / Error)

### 将来要件

- メール本文プレビュー
- 添付ファイルプレビュー
- 失敗ジョブの再実行導線

---

## 7. Queue 表示

### 将来要件

- 実行待ち件数
- 実行中 / 完了 / Error 件数
- アカウント別の集計

---

## 8. エラー / 通知

### 必須情報

- ルール保存時の検証エラー
- 接続エラー

### 将来要件

- カテゴリ別エラー表示
- 連続失敗時のアカウント自動停止

---

# メール監視画面の代表的な画面分割

現在の実装状況・将来要件・AI-OCR 製品の実例を踏まえ、
メール監視画面のレイアウト案を以下の 2 軸 × 3 パターンで整理する。

- **将来設計なし版**(現実装寄り) … パターン①〜③
- **将来設計あり版**(AI-OCR 完成系寄り) … パターン④〜⑥

---

## 前提整理

| 方針 | 評価 |
| ---- | -- |
| アカウント → ルールの分離 | ◎ |
| ルール優先度の管理 | ◎ |
| OCR 連携(Provider/Engine/Template) | ◎ |
| 接続状態の可視化 | ◎ |

---

# 将来設計なし版(現実装ベース)

---

## パターン① シンプル業務型(DX Suite 系)

1 画面フォーム + ルール一覧。

### 画面図

```text
┌──────────────────────────────┐
│ メールアカウント             │
│ [ support@example.com ]      │
│                              │
│ OCRルール                    │
│ ・invoice → 請求書OCR        │
│ ・order   → 注文書OCR        │
│                              │
│ ☑ 自動OCR有効               │
│                              │
│ [保存]                       │
└──────────────────────────────┘
```

### 分割思想

```text
1画面フォーム型
```

### メリット

| 項目 | 評価 |
| ---- | -- |
| わかりやすい | ◎ |
| 学習コスト低い | ◎ |
| 小規模向き | ◎ |

### デメリット

| 項目 | 評価 |
| ---- | -- |
| 大量ルール弱い | △ |
| 拡張性弱い | △ |

### 向いている

```text
・小規模運用
・簡易OCR
```
