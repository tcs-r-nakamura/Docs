# 設定画面 パターン比較

以下に、AI-OCRで実際にあり得る
設定画面の構成案を複数提示します。

---

# 凡例

各セクションで使う見出しの意味:

- **必須情報**
  - 設定画面に存在する/載せるべき項目
- **関連実装(他画面)**
  - 設定画面外で既に実装されている関連機能(参考用)
- **将来要件**
  - 設定画面に追加する予定/検討中の機能
- **注意事項**
  - 実装上の制約・設計上の前提・既知の挙動など、画面利用時の留意点

---

# 設定画面に必要な画面情報

---

## 1. グローバル設定

### 必須情報

- API Endpoint (バックエンド接続先)
- 接続テスト
- テーマ(ライト / ダーク)
- 言語(日本語 / 英語)

### 将来要件

- リトライ / タイムアウト等の通信設定
- ログ出力レベル

---

## 2. OCR Provider 接続設定

### 必須情報

- Provider 単位の API Key / Endpoint 設定
  - mock / azure / google / paddleocr / yomitoku / gemini / qwen
- Provider 別の接続テスト
- 接続状態表示(OK / NG)

### 将来要件

- Provider 追加 UI
- 認証方式の追加(OAuth / 環境変数経由など)

### 注意事項

- Provider 一覧はサーバー側の `scripts/init/engines.json` に依存
- 追加 Provider のためのクライアント側 UI 拡張が必要

---

## 3. 画面別設定

### 必須情報

- OCR 実行画面の既定値
  - 既定 Provider / Engine / Template / 言語
- 結果確認画面の表示設定
  - 既定の confidence 閾値ハイライト

### 将来要件

- 各画面ごとのレイアウト/列幅などの保存

---

## 4. 使用量・コスト

### 必須情報

- 合計ページ数
- 推定コスト(¥表記)
- Provider 別の TotalPages / TotalCost
- 「更新」ボタンで再取得

### 関連実装(他画面)

- 単価は `t_engine_pricing_set` で履歴管理
  - 実行時点の単価で `t_usage_recorded` にスナップショット記録
- 通貨はデフォルト JPY(エンジン単位で変更可)

### 将来要件

- 期間指定(月次 / 任意レンジ)での集計
- ユーザー / 部署別の利用状況
- CSV エクスポート

### 注意事項

- 画面注記:
  「※ 推定コストは各社公式料金を基に算出した目安です。
    実際の請求額とは異なる場合があります。」

---

## 5. ライセンス情報

### 必須情報

- ライセンス種別
- 有効期限
- 利用上限(ページ数 / ジョブ数)

### 将来要件

- 上限警告通知
- ライセンス更新導線

---

## 6. ユーザー / 権限管理

### 将来要件

- ログインユーザー情報
- ロール(管理者 / 一般 / 閲覧専用)
- 監査ログ

### 注意事項

- 現状はシングルユーザー前提
- 多ユーザー化は API 側の認証基盤整備とセットでの将来要件

---

## 7. エラー / 通知

### 必須情報

- 接続失敗時のエラーメッセージ
- 保存時のバリデーションエラー表示

### 将来要件

- `ErrorHandler` 共通基盤の活用
  - 認証 / 入力 / サーバー / タイムアウトのカテゴリ別表示

---

# 設定画面の代表的な画面分割

現在の実装状況・将来要件・AI-OCR 製品の実例を踏まえ、
設定画面のレイアウト案を以下の 2 軸 × 3 パターンで整理する。

- **将来設計なし版**(現実装寄り) … パターン①〜③
- **将来設計あり版**(AI-OCR 完成系寄り) … パターン④〜⑥

---

## 前提整理

| 方針 | 評価 |
| ---- | -- |
| シンプル整理(現状 Accordion 型) | ◎ |
| OCR Provider 接続設定が中核 | ◎ |
| 使用量表示は本画面に集約 | ◎ |
| 画面別設定は別グループに分離 | ◎ |

---

```text
┌────────────────────────────────────┐

├────────────────────────────────────┤

│ ▼ Google                           │
│ ▼ PaddleOCR                        │
└────────────────────────────────────┘

┌────────────────────────────────────┐
│ 使用量                             │
├────────────────────────────────────┤
│ Azure   1200 pages / ¥1,200        │
│ Google   320 pages /   ¥320        │
└────────────────────────────────────┘
```

### 画面分割

```text
縦セクション型
```

| 項目 | 評価 |

| 項目 | 評価 |
| ---- | -- |
| スクロール増える | △ |

```text
・初期構築
・小〜中規模
・シンプル運用
```

上部タブで設定カテゴリを切替。

### 画面図

```text

│ [接続] [画面別] [使用量] [License] │
├────────────────────────────────────┤
│ API Endpoint                       │
│ [ https://xxxx ]                   │
│ API Key                            │
│ [ ************** ]                 │
│ ☑ ダークモード                    │
│ [接続テスト]  [保存]               │
└────────────────────────────────────┘
```

### 分割思想

- タブで意味カテゴリを分離
- 同時に見えるのは 1 カテゴリのみ

### メリット

| 項目 | 評価 |
| ---- | -- |
| 学習コスト低い | ◎ |
| UI 軽い | ◎ |
| 小規模向き | ◎ |

### デメリット

| 項目 | 評価 |
| ---- | -- |
| 拡張性弱い | △ |
| Provider 増加に弱い | △ |

### 向いている

```text
・中小規模
・簡易OCR
```
