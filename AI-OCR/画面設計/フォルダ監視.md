# フォルダ監視画面 パターン比較

以下に、AI-OCRで実際にあり得る
フォルダ監視画面の構成案を複数提示します。

---

# 凡例

各セクションで使う見出しの意味:

- **必須情報**
  - フォルダ監視画面に存在する/載せるべき項目
- **関連実装(他画面)**
  - フォルダ監視画面外で既に実装されている関連機能(参考用)
- **将来要件**
  - フォルダ監視画面に追加する予定/検討中の機能
- **注意事項**
  - 実装上の制約・設計上の前提・既知の挙動など、画面利用時の留意点

---

# フォルダ監視画面に必要な画面情報

フォルダ監視は単なる「ファイル検知」ではなく、自動 OCR パイプライン(検知 〜 OCR 投入 〜 結果保存)の起点となる画面である。

```text
ファイル投入
↓
検知
↓
ルール判定
↓
OCR Engine選択
↓
Template選択
↓
OCR投入
↓
結果保存
```

---

## 1. 監視フォルダ管理

### 必須情報

- 監視フォルダの追加・編集・削除
- フォルダパス
- 有効/無効切替
- ポーリング間隔 / FileSystemWatcher 方式の選択

### 将来要件

- フォルダ別の保留ファイル上限
- ネットワーク共有(UNC / SMB)対応
- クラウドストレージ(S3 / OneDrive / SharePoint)対応

### 注意事項

- ネットワーク共有はファイルロック解放タイミングの考慮が必要

---

## 2. ルール一覧(最重要)

### 必須情報

- ルール名 / 有効フラグ
- 拡張子条件(`*.pdf` / `*.jpg` など)
- ファイル名条件(Regex / 前方一致)
- 適用 OCR Provider / Engine
- 適用テンプレート
- 優先度
- 処理後のファイル移動先

### 将来要件

- ルールの並べ替え(優先度ドラッグ)
- ルール複製・テンプレート化
- 処理後のファイル削除/アーカイブ設定

---

## 3. ルール詳細編集

### 必須情報

- 上記フィールドの編集 UI
- 保存・キャンセル
- バリデーション(Regex 構文・必須項目)

### 将来要件

- IF...THEN 形式の条件ビルダー
- ドライラン(テストファイル投入で確認)

---

## 4. フォルダ状態

### 必須情報

- フォルダ別の監視ステータス(Monitoring / Error / Polling)
- 直近の検知時刻
- 直近のエラー内容

### 将来要件

- 検知失敗時の自動リトライ
- アラート通知

---

## 5. テスト投入

### 将来要件

- 「テストファイル投入」ボタン
- 適用ルールのドライラン表示

### 注意事項

- 本番運用前のルール検証手段がないと誤判定で OCR コストが膨らむため必須化したい

---

## 6. 処理履歴

### 必須情報

- 検知ファイル一覧
- 適用ルール / OCR 結果リンク
- 処理ステータス(検知 / OCR 中 / 完了 / Error)
- 移動先パス

### 将来要件

- ファイルプレビュー
- 失敗ジョブの再実行導線

---

## 7. Queue 表示

### 将来要件

- 実行待ち件数
- 実行中 / 完了 / Error 件数
- フォルダ別の集計

---

## 8. ファイル後処理

### 必須情報

- 処理成功時の移動先(`processed/`)
- 処理失敗時の移動先(`error/`)
- 元ファイルの削除/保持

### 将来要件

- 連携先(S3 / SharePoint / 共有フォルダ等)への自動エクスポート
- リネームルール

---

## 9. エラー / 通知

### 必須情報

- ルール保存時の検証エラー
- フォルダアクセスエラー(権限/パス無効)

### 将来要件

- カテゴリ別エラー表示
- 連続失敗時のフォルダ自動停止

---

# フォルダ監視画面の代表的な画面分割

現在の実装状況・将来要件・AI-OCR 製品の実例を踏まえ、
フォルダ監視画面のレイアウト案を以下の 2 軸 × 3 パターンで整理する。

- **将来設計なし版**(現実装寄り) … パターン①〜③
- **将来設計あり版**(AI-OCR 完成系寄り) … パターン④〜⑥

---

## 前提整理

| 方針 | 評価 |
| ---- | -- |
| フォルダ → ルールの分離 | ◎ |
| ルール優先度の管理 | ◎ |
| OCR 連携(Provider/Engine/Template) | ◎ |
| ファイル移動の設定 | ◎ |
| メール監視画面と UI 共通化可 | ◎ |

---

# 将来設計なし版(現実装ベース)

---

## パターン① シンプル業務型(DX Suite 系)

1 画面フォーム + ルール一覧。

### 画面図

```text
┌──────────────────────────────┐
│ 監視フォルダ                 │
│ [ C:\OCR\Input ]             │
│                              │
│ OCRルール                    │
│ ・*.pdf → 請求書OCR          │
│ ・*.jpg → 名刺OCR            │
│                              │
│ ☑ 自動OCR有効               │
│                              │
│ [保存]                       │
└──────────────────────────────┘
```

### 分割思想

```text
1画面フォーム型
```

### メリット

| 項目 | 評価 |
| ---- | -- |
| わかりやすい | ◎ |
| 学習コスト低い | ◎ |
| 小規模向き | ◎ |

### デメリット

| 項目 | 評価 |
| ---- | -- |
| 大量ルール弱い | △ |
| 拡張性弱い | △ |

### 向いている

```text
・小規模OCR
・簡易運用
```

## パターン③ 3ペイン運用型(UiPath 系・推奨)

### 画面図

```text
┌────────────┬──────────────────────┬──────────────┐
│ フォルダ一覧│ ルール一覧            │ ルール詳細    │
│            │                      │              │

│            │                      │ Move Folder  │
│            │                      │ [保存]       │
```

| 右 | ルール詳細 |

| 項目 | 評価 |

