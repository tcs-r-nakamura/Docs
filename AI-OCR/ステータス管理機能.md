# ResultView 確認ステータス管理機能 設計書

**機能名**: OCR結果一覧 確認ステータス管理
**対象画面**: ResultView

---

## 1. 背景・目的

OCR結果の運用フローにおいて、各 OCR 結果がオペレーターにより「確認済みか否か」「修正が行われたか」を把握できないという課題がある。本機能は OCR 結果ごとに確認ステータスを記録・表示・絞り込みできるようにし、確認作業の進捗管理と品質追跡を可能にする。

---

## 2. 現状確認

### 2-1. ResultView 構造

| ペイン | 幅 | 内容 |
|--------|-----|------|
| 左 | 250px | ジョブ履歴リスト + 検索・フィルタ |
| 中央 | * | 画像ビューア（バウンディングボックス付き） |
| 右 | 350px | テキストパネル（編集・Undo/Redo） |

### 2-2. 既存フィルタ

| フィルタ | 種別 | バインディング |
|---------|------|--------------|
| テキスト検索 | TextBox | `SearchQuery` |
| ステータス（ジョブ + 確認） | 統合フィルターパネル（チェックボックス） | `StatusFilters`（`HashSet<string>`） |
| 投入日 | 統合フィルターパネル（DatePicker × 2） | `DateFrom` / `DateTo` |

フィルタは `FilteredJobHistory`（LINQ / in-memory）で即時反映される。既存の `StatusFilter`（`string?` 単一選択 ComboBox）と `IsDateFilterVisible` / `OpenDateFilterCommand` 等は統合フィルターパネルに置き換える（§5 参照）。

### 2-3. 既存ステータス体系との区別

現在 `JobStatus`（`OcrViewer.Sdk/Domain/ValueObjects/JobStatus.cs`）が OCR パイプラインの処理状態（`Queued` / `Running` / `Succeeded` / `Failed` / `Canceled`）を管理している。本機能で追加する「確認ステータス」はこれとは独立した概念であり、OCR 処理が完了（`Succeeded`）した後のオペレーター確認フェーズを表す。混同を避けるため型名は `ReviewStatus` とし、UI でも「ジョブステータス」と「確認ステータス」を明確に区別する。

### 2-4. 永続化の仕組み

本システムはマルチユーザー対応のため、**確認ステータスおよびジョブ一覧はサーバー側 PostgreSQL に保存する**。クライアントは API を介してデータの読み書きを行う。

**サーバー側（新規追加）**:

| テーブル | プレフィックス | 役割 |
|---------|-------------|------|
| `a_job_review` | `a_`（属性） | ジョブ単位のレビューサマリー（`m_job` と 1:1） |
| `t_job_block_review_set` | `t_`（イベント） | TextBlock 単位のレビュー操作履歴（追記のみ） |

**`a_job_review` カラム定義**:

| カラム名 | 型 | 説明 |
|--------|-----|------|
| `job_id` | INTEGER（PK、FK → `m_job.id`） | ジョブ ID |
| `summary_status` | VARCHAR(20) | ジョブ全体の確認状態（`"unreviewed"` / `"completed"` / `null`（succeeded 以外）） |
| `updated_at` | TIMESTAMPTZ | 最終更新日時（ジョブ成功時は `succeeded_at` と同値、レビュー更新時は `reviewed_at` と同値） |

**`t_job_block_review_set` カラム定義**:

| カラム名 | 型 | 説明 |
|--------|-----|------|
| `id` | SERIAL（PK） | 自動採番 |
| `job_id` | INTEGER（FK → `m_job.id`、index） | ジョブ ID |
| `page_no` | INTEGER | ページ番号（1 始まり） |
| `block_type` | VARCHAR(20) | `"line"` / `"word"` / `"table"` |
| `block_index` | INTEGER | そのページ内の配列インデックス（0 始まり） |
| `review_status` | VARCHAR(20) | `"unreviewed"` / `"completed"` / `"completed_with_edit"` |
| `edited_text` | TEXT（NULL 可） | テキスト修正内容（ジョブ再表示時に復元する。修正がない場合は NULL） |
| `reviewed_at` | TIMESTAMPTZ | 操作日時 |

> **イベントソーシング**: `t_job_block_review_set` は操作のたびに INSERT する（UPDATE / DELETE 禁止）。最新状態は `job_id` + `page_no` + `block_type` + `block_index` でグループ化し、最大 `id` の行を使う。

> **`a_job_review` の作成タイミング**: `m_job` の INSERT と同一トランザクションで INSERT する（既存の `a_*` テーブルと同じパターン）。作成時は `summary_status = null` で初期化し、`t_job_succeeded` 記録と同一トランザクションで `summary_status = 'unreviewed'` に UPDATE する。`failed`・`canceled`・`running`・`queued` のジョブは `summary_status` が `null` のまま維持される（「レビュー対象外」を意味する）。`GET /v1/jobs` は `m_job` と `a_job_review` を INNER JOIN で取得できる。

> **`block_index` の安定性と `page_no` の変換**: `block_index` は OCR 結果 JSON（`result_path`）の `page.words` / `page.lines` / `page.tables` の配列インデックス（0 始まり）に対応する。ジョブは `SUCCEEDED` 後に再処理されないため配列順は不変である。クライアント側の `CurrentPageIndex`（0 始まり）に対し、`page_no` は 1 始まりのため、実装時は `page_no = CurrentPageIndex + 1` で変換する。

**クライアント側**:

- ジョブ一覧は `GET /v1/jobs` API から取得する（`job-history.json` をジョブ一覧として使わない）
- `job-history.json` は `FilePath`（OCR 対象画像のローカルパス）のみ保持し、画像表示のキャッシュとして使う
- TextBlock 単位のレビュー状態は `GET /v1/jobs/{job_id}/review-state` API から取得し、ローカルには保持しない
- ジョブ表示時は OCR 結果 JSON を読み込んだ後に `GET /v1/jobs/{job_id}/review-state` を呼び出し、`edited_text` が存在するブロックのテキストを上書きして表示する（`review_status` が `"completed_with_edit"` のブロックのみ上書き対象）

**新規 API エンドポイント**:

| メソッド | パス | 用途 |
|---------|------|------|
| `GET` | `/v1/jobs` | ジョブ一覧取得（レビューサマリーを含む） |
| `GET` | `/v1/jobs/{job_id}/review-state` | TextBlock 単位のレビュー状態取得（`review_status` / `edited_text` を含む） |
| `PATCH` | `/v1/jobs/{job_id}/review-state` | 1ブロック分のレビュー状態を更新（差分更新） |

**`GET /v1/jobs/{job_id}/review-state` レスポンス**:

レビュー操作済みのブロックのみを配列で返す（既存の `GET /v1/results/{job_id}` と同じく全件一括返却・ページネーションなし）。レスポンスに含まれないブロックはクライアントが `"unreviewed"` として扱う。

| フィールド名 | 型 | 説明 |
|------------|-----|------|
| `page_no` | INTEGER | ページ番号（1始まり） |
| `block_type` | STRING | `"line"` / `"word"` / `"table"` |
| `block_index` | INTEGER | そのページ内の配列インデックス（0始まり） |
| `review_status` | STRING | `"completed"` / `"completed_with_edit"` |
| `edited_text` | STRING \| NULL | 修正テキスト（`"completed_with_edit"` のときのみ非 `null`） |

**`PATCH /v1/jobs/{job_id}/review-state` リクエストボディ**:

| フィールド名 | 型 | 必須 | 説明 |
|------------|-----|------|------|
| `page_no` | INTEGER | ○ | ページ番号（1始まり） |
| `block_type` | STRING | ○ | `"line"` / `"word"` / `"table"` |
| `block_index` | INTEGER | ○ | そのページ内の配列インデックス（0始まり） |
| `review_status` | STRING | ○ | `"unreviewed"` / `"completed"` / `"completed_with_edit"` |
| `edited_text` | STRING \| NULL | △ | `review_status` が `"completed_with_edit"` のとき必須。それ以外は `null` |

> **1リクエスト = 1ブロック**: 1回の `PATCH` で更新するブロックは1件のみ。サーバーは受信のたびに `t_job_block_review_set` へ1行 INSERT し、`a_job_review.summary_status` を再集計して UPDATE する（同一トランザクション）。

> **`summary_status` の再集計ルール**: `PATCH` 処理時、サーバーは `t_job_block_review_set` から当該ジョブの全ブロックの最新状態（`job_id` でグループ化し最大 `id` の行）を取得して以下のルールで集計する。1件でも `"unreviewed"` があれば `"unreviewed"`、全件が `"completed"` または `"completed_with_edit"` であれば `"completed"` を `a_job_review.summary_status` にセットする。`summary_status` は常に `t_job_block_review_set` から再計算可能である。

**`GET /v1/jobs` レスポンスフィールド**:

| フィールド名 | 型 | 取得元 | 説明 |
|------------|-----|--------|------|
| `reportId` | INTEGER | `m_job.id` | ジョブ ID |
| `fileName` | STRING | `m_job.original_filename` | ファイル名 |
| `fileSizeBytes` | INTEGER | `m_job.file_size_bytes` | ファイルサイズ（バイト） |
| `createdAt` | TIMESTAMPTZ | `m_job.created_at` | 投入日時 |
| `status` | STRING | イベントテーブルから導出（既存 `GET /v1/statuses/{job_id}` と同ロジック） | `"queued"` / `"running"` / `"succeeded"` / `"failed"` / `"canceled"` |
| `provider` | STRING | `m_provider` JOIN | OCR プロバイダー名 |
| `engine` | STRING \| NULL | `m_engine` JOIN | OCR エンジン名 |
| `summaryStatus` | STRING \| NULL | `a_job_review.summary_status`（INNER JOIN） | `"unreviewed"` / `"completed"` / `null`（`succeeded` 以外のジョブは `null`） |

> **`filePath` はレスポンスに含まない**: `filePath` はクライアントがジョブ投入時に使用したローカルファイルパスであり、サーバーは保持しない。クライアントは `reportId` をキーとして `job-history.json` から `filePath` を引く（画像表示のキャッシュ用途）。

> **既存エンドポイントへの影響なし**: `GET /v1/statuses/{job_id}`・`GET /v1/results/{job_id}` の仕様は変更しない。


**パネルを閉じた後のヘッダー表示**

```
┌────────────────────────────────┐
│ ジョブ履歴          [▼(3)]     │
│ 成功・失敗 かつ 未確認          │  ← FilterSummary（条件サマリー）
├────────────────────────────────┤
│ [🔍 検索...]                   │
└────────────────────────────────┘
```

- ポップアップ外クリックで自動クローズ（`Escape` キーでも閉じる）

- 1件以上の条件が有効なとき、ヘッダーアイコンに件数バッジと `FilterSummary` を表示

### 3-2. 画面項目定義

| 項目名 | 種別 | バインディング | 初期値 | 役割 |
|--------|------|--------------|--------|------|
| 統合フィルターアイコン | Button | `ResultViewModel.OpenFilterPanelCommand` | — | パネル開閉。条件数バッジ（`FilterActiveCount`）と `FilterSummary` を重ねて表示 |
| 統合フィルターパネル | Popup/Border | `ResultViewModel.IsFilterPanelVisible` | 非表示 | 投入日・ステータスをまとめて設定 |

| 確認ステータス チェックボックス群 | CheckBox × 2 | `ResultViewModel.ToggleReviewStatusFilterCommand(string key)` | 全未選択 | 完了／未確認 の複数選択（セクション内 OR、ジョブステータスと AND） |
| フィルター条件サマリー | TextBlock | `ResultViewModel.FilterSummary` | 非表示 | パネルを閉じた後にヘッダー下へ適用中の条件を日本語で表示（例:「成功・失敗 かつ 未確認」） |

| 確認ステータスバッジ（一覧行） | Border + TextBlock | `JobHistoryItemViewModel.ReviewStatusBadgeDisplay`（ラベル）/ `ReviewStatusKey`（DataTrigger 色切り替え） | 「未確認」 | 各ジョブの確認状態をラベル表示（succeeded のみ表示、完了 / 未確認 の2値） |
| 編集モード切り替えボタン（[✏]） | ToggleButton | `ResultViewModel.IsEditMode` | OFF | ON 時に全 TextBlock を TextBox に切り替え。ON 状態でアイコン強調表示 |
| 一括完了ボタン | Button | `ResultViewModel.BulkCompleteUnreviewedCommand` | 非活性 | 現在ページの「未確認」TextBlock をすべて「完了」に変更（修正完了は変更しない） |
| TextBlock ステータスボタン（Right Pane 各行） | Button | `TextBlockViewModel.ReviewStatusKey` / `ToggleTextBlockReviewCommand` | 「確認済みにする」 | 状態に応じたラベルを表示。「確認済みにする」→完了、「未確認に戻す」→未確認、「OCRに戻す」→確認ダイアログ後にテキスト破棄+未確認。テキスト確定で自動遷移あり |

**確認ステータスバッジ カラーマッピング**

ジョブ一覧行のバッジは「完了」と「未確認」の2値のみを表示する。`CompletedWithEdit`（修正完了）は TextBlock 単位のステータスであり、ジョブ行バッジには表示しない。

| 値 | 表示文字列 | バッジ色 | 表示箇所 |
|----|-----------|---------|---------|
| `Unreviewed` | 未確認 | グレー `#E9ECEF` | ジョブ一覧バッジ |
| `Completed` | 完了 | 青 `#CCE5FF` | ジョブ一覧バッジ |
| `CompletedWithEdit` | 修正完了 | 緑 `#D4EDDA` | TextBlock 単位（Right Pane）のみ |

`ReviewStatusDisplay` は上記の日本語文字列を返す（表示専用）。ステータスフィルターのチェックボックス Tag 値は英語小文字（`"completed"`）を使用し、`FilteredJobHistory` 内で `_statusFilters.Contains(j.ReviewStatusKey)` で比較する。DataTrigger によるバッジ色切り替えも同じ `ReviewStatusKey` を使用する。

### 3-3. ユーザー操作と挙動

| 操作 | 挙動 |
|------|------|
| ジョブ履歴から項目を選択 | Right Pane に OCR 結果を表示。編集モードは OFF にリセット |
| [✏] ボタンを押下 | 編集モード ON：全 TextBlock が TextBox に切り替わる。ボタン強調表示 |
| 再度 [✏] ボタンを押下 | 編集モード OFF：全 TextBlock が表示モードに戻る |
| 編集モード ON 中に Tab キー | 現在の TextBox から次の TextBox へフォーカス移動 |
| 編集モード ON 中にテキストを確定（✓ または Tab） | 最初の OCR 結果と異なる場合 → 「修正完了」に自動遷移。元のテキストと同じ場合 → 「未確認」に戻す。Left Pane のジョブバッジも即時更新 |
| 「すべて完了にする」ボタンをクリック | 確認ダイアログを表示（例:「このページの未確認 3 件を完了にしますか？」）。「はい」→ 現在ページの「未確認」TextBlock をすべて「完了」に変更。「完了」「修正完了」は変更しない |
| TextBlock の「確認済みにする」ボタンをクリック | 「完了」に遷移 |
| TextBlock の「未確認に戻す」ボタンをクリック | 「未確認」に遷移（見直しのための戻し） |
| TextBlock の「OCRに戻す」ボタンをクリック | 確認ダイアログを表示。「はい」→ テキストを最初の OCR 結果に戻し「未確認」に遷移。「いいえ」→ 何もしない |
| [▼] アイコンをクリック | 統合フィルターパネルを開く |
| フィルターパネル外をクリック / Escape キー | 統合フィルターパネルを閉じる |
| ジョブ／確認ステータス チェックボックスをクリック | `FilteredJobHistory` を再評価し一覧を絞り込み。同セクション内は OR、セクション間および投入日は AND 結合。`FilterSummary` を即時更新 |
| 「すべてクリア」ボタンをクリック | 投入日・ステータス両フィルターをリセット |

### 3-4. ボタン活性制御

| ボタン | 条件 | 状態 |
|--------|------|------|
| [✏] 編集モード切り替え | ジョブ未選択 または `JobStatus` が `Succeeded` 以外 | 非活性 |
| [✏] 編集モード切り替え | `JobStatus` が `Succeeded` | 活性 |
| すべて完了にする | 現在ページに「未確認」の TextBlock が1件以上ある | 活性 |
| すべて完了にする | 「未確認」の TextBlock が0件 | 非活性 |

## 4. 機能仕様

### 4-1. 確認ステータス定義

| 値 | 意味 |
|----|------|
| `Unreviewed`（未確認） | 初期状態（新規ジョブ登録時に自動付与） |
| `CompletedWithEdit`（修正完了） | OCR 結果を編集して確認済み |
| `Completed`（完了） | OCR 結果を編集せず確認済み |

### 4-2. ステータス遷移

**前提**:
- `Completed`（完了）状態では、テキストは常に OCR 初期値と同一である（`HasChanges = false`）
- `CompletedWithEdit`（修正完了）状態では、テキストは OCR 初期値と異なる（`HasChanges = true`）

**ステータスボタン**:

| 現在のステータス | 表示するボタン |
|----------------|--------------|
| `Unreviewed` | 「確認済みにする」 |
| `Completed` または `CompletedWithEdit` | 「未確認に戻す」 |

「未確認に戻す」の動作:
- `ResetToOriginal()` でテキストを OCR 初期値に戻し、`ReviewStatus = Unreviewed` に変更する
- `CompletedWithEdit` から押した場合のみ確認ダイアログを表示する（編集内容が失われるため）
- `Completed` から押した場合はダイアログなし（テキストは既に初期値のため実質変化なし）

**遷移テーブル**:

| 操作（トリガー） | 遷移元 | 遷移先 | 備考 |
|----------------|--------|--------|------|
| ジョブ登録 | — | `Unreviewed` | 初期状態 |
| 「確認済みにする」クリック | `Unreviewed` | `Completed` | テキスト変化なし |
| テキスト確定（変更あり） | `Unreviewed` | `CompletedWithEdit` | |
| テキスト確定（変更あり） | `Completed` | `CompletedWithEdit` | 完了でも編集があれば修正完了へ |
| テキスト確定（変更あり） | `CompletedWithEdit` | `CompletedWithEdit` | 自己遷移（修正内容を上書き） |
| テキスト確定（変更なし） | `CompletedWithEdit` | `Unreviewed` | 元に戻したら未確認へ |
| テキスト確定（変更なし） | `Completed` | `Completed` | 変化なし |
| テキスト確定（変更なし） | `Unreviewed` | `Unreviewed` | 変化なし |
| 「未確認に戻す」クリック | `Completed` | `Unreviewed` | `ResetToOriginal()` 実行。ダイアログなし |
| 「未確認に戻す」→「はい」 | `CompletedWithEdit` | `Unreviewed` | `ResetToOriginal()` 実行。確認ダイアログあり |
| 「すべて完了にする」→「はい」 | `Unreviewed`（対象のみ） | `Completed` | `CompletedWithEdit` は対象外 |

### 4-3. ジョブ単位のステータス集計ルール

**前提**: `Succeeded` のジョブには必ず1件以上の TextBlock が存在する。TextBlock が0件の場合は未取得（そのジョブをまだ開いていない）として扱う。

**集計ルール**:

| TextBlock の状態 | ジョブバッジ表示 |
|-----------------|----------------|
| 1件でも `Unreviewed` がある | **未確認**（グレー） |
| 全件が `Completed` または `CompletedWithEdit` | **完了**（青） |
| `JobStatus` が `Succeeded` 以外 | バッジを表示しない |

- `CompletedWithEdit` は集計上「完了」として扱う
- 不正値（JSON 読み込み時の未知文字列等）は `Unreviewed` として扱う（TextBlock 個別・ジョブ集計値ともに同様）

**バッジ値の保持**:

各 `JobHistoryItemViewModel` は自身のレビュー集計値（`ReviewStatusKey`）を保持する。最新の集計結果を `ReviewStatusKey` に保持し、未ロード時のみ永続化値で初期表示する。

| 状況 | 集計値の取得元 |
|------|-------------|
| TextBlock 未取得（未選択） | `JobHistoryItem`（JSON から読み込んだ永続化値） |
| TextBlock 取得済み | TextBlock を全件走査して算出した値 |

**集計タイミング**:

| タイミング | 処理 |
|----------|------|
| `LoadResultAsync` 完了時 | 永続化済みの各 TextBlock の `ReviewStatus` を設定し、集計を初期化する |
| TextBlock のステータスが変わったとき | 即時に集計しなおし、`ReviewStatusKey` を更新する |
| 別のジョブに切り替えたとき | 切り替え前のジョブの `ReviewStatusKey` は最後の集計値を維持する |

**集計の流れ**:

```
TextBlock のステータスが変わる
         ↓
ResultViewModel が変化を検知
         ↓
SelectedHistoryItem.UpdateReviewStatus(TextBlocks) を呼ぶ
         ↓
全 TextBlock を走査して集計
（1件でも Unreviewed → "unreviewed"、全件 Completed/CompletedWithEdit → "completed"）
         ↓
ReviewStatusKey プロパティを更新 → Left Pane バッジが即時更新される
         ↓
IJobHistoryRepositoryPort.Update() で永続化する
```

### 4-4. 永続化データ構造

**追加フィールド**:

| 場所 | フィールド名 | 型 | 説明 |
|------|------------|-----|------|
| `JobHistoryItemDto`（保存用） | `textBlockReviews` | `Dictionary<string, string>?` | null 可。欠落時は後方互換 |
| `JobHistoryItem`（ドメインモデル） | `TextBlockReviews` | `IReadOnlyDictionary<string, ReviewStatus>` | 読み取り専用。更新時は再生成して差し替え。デフォルトは空辞書 |

**キー設計（`"{pageIndex}_{type}_{itemIndex}"`）**:

| 部位 | 内容 |
|------|------|
| `pageIndex` | ページ番号（0始まり・整数） |
| `type` | `"line"` / `"word"` / `"table"` |
| `itemIndex` | そのページ内の配列インデックス（0始まり・整数） |

> **前提**: 同一 `reportId` の OCR 結果はサーバー保存済みの固定データのため、取得のたびに配列順は変わらない。

**読み飛ばし条件**（以下のいずれかに該当するキーは無視する）:

- `pageIndex` または `itemIndex` が整数でない、または負数
- 区切り（`_`）が2つでない（形式不正）
- `type` が `"line"` / `"word"` / `"table"` 以外

**値の設計**:

| 値 | 意味 |
|----|------|
| `"unreviewed"` | 未確認 |
| `"completed"` | 完了 |
| `"completedWithEdit"` | 修正完了 |
| 不明な値 | `Unreviewed` として扱う（`JobStatus.FromString()` と同じルール） |

**ToDto / FromDto の更新方針**:

```
復元時（FromDto）:
  textBlockReviews が null / 欠落 → 空辞書（全件 Unreviewed 扱い）
  textBlockReviews が存在する    → キーはそのまま、値は ReviewStatus.FromKey() で変換
                                   ※ 不正キーは読み飛ばし、不明値は Unreviewed

保存時（ToDto）:
  TextBlockReviews の値を ReviewStatus.ToKey() で文字列に変換して保存
```

**変換例**（既存の `Status` フィールドと同じパターン）:

```csharp
// 保存時（ToDto）
TextBlockReviews = item.TextBlockReviews
    .ToDictionary(kv => kv.Key, kv => kv.Value.ToKey())
// ReviewStatus.Completed → "completed"

// 読込時（FromDto）
TextBlockReviews = dto.TextBlockReviews
    ?.ToDictionary(kv => kv.Key, kv => ReviewStatus.FromKey(kv.Value))
    ?? new Dictionary<string, ReviewStatus>()
// フィールドなし → 空辞書（全件 Unreviewed 扱い）
```

**JSON イメージ**:

```json
{
  "reportId": "42",
  "fileName": "document.pdf",
  "status": "succeeded",
  "textBlockReviews": {
    "0_line_0": "completed",
    "0_line_1": "completedWithEdit",
    "0_word_0": "unreviewed"
  }
}
```

**後方互換**:

`textBlockReviews` が存在しない・`null`・空オブジェクト `{}` はすべて同一に扱い、全 TextBlock を `Unreviewed` に初期化する（区別不要）。

## 6. 実装方針（概要）

### 6-1. ReviewStatus 型

`enum` を `Domain/Models/` に独立ファイルとして配置し（`MatchType` と同じ namespace）、変換・表示用メソッドを `static` 拡張クラス（`ReviewStatusExtensions.cs`）に分離する（`MatchTypeExtensions.cs` と同じ場所）。

```csharp
// ReviewStatus.cs
public enum ReviewStatus { Unreviewed, Completed, CompletedWithEdit }

// ReviewStatusExtensions.cs
public static class ReviewStatusExtensions
{
    public static ReviewStatus FromKey(string value) => value switch
    {
        "completed"         => ReviewStatus.Completed,
        "completedWithEdit" => ReviewStatus.CompletedWithEdit,
        _                   => ReviewStatus.Unreviewed
    };
    public static string ToKey(this ReviewStatus s) => s switch
    {
        ReviewStatus.Completed         => "completed",
        ReviewStatus.CompletedWithEdit => "completedWithEdit",
        _                              => "unreviewed"
    };
    public static string ToDisplay(this ReviewStatus s) => s switch
    {
        ReviewStatus.Completed         => "完了",
        ReviewStatus.CompletedWithEdit => "修正完了",
        _                              => "未確認"
    };
}
```

### 6-2. TextBlockViewModel への追加

`ReviewStatus` は `[ObservableProperty]` で管理し、`[NotifyCanExecuteChangedFor]` でボタンの活性制御を自動化する（既存の `_isDateFilterVisible` + `[NotifyCanExecuteChangedFor]` と同じパターン）。

`TextBlockKey` は ResultViewModel 側から付与し、TextBlockViewModel は `init` プロパティで受け取るだけ。

```csharp
[ObservableProperty]
[NotifyCanExecuteChangedFor(nameof(MarkCompleteCommand))]
[NotifyCanExecuteChangedFor(nameof(MarkUnreviewedCommand))]
private ReviewStatus _reviewStatus;

public string? TextBlockKey { get; init; }

// CommitEdit() の変更箇所（レビュー状態遷移のみここに集約。Undo/Redo 登録は既存3経路どおり）
public void CommitEdit()
{
    Text = EditingText;
    IsEditing = false;
    OnPropertyChanged(nameof(HasChanges));

    if (HasChanges)
        ReviewStatus = ReviewStatus.CompletedWithEdit;
    else if (ReviewStatus == ReviewStatus.CompletedWithEdit)
        ReviewStatus = ReviewStatus.Unreviewed;
    // Completed + 変更なし → そのまま維持
}

// 「確認済みにする」ボタン（Unreviewed のときのみ活性）
[RelayCommand(CanExecute = nameof(CanMarkComplete))]
private void MarkComplete() => ReviewStatus = ReviewStatus.Completed;
private bool CanMarkComplete() => ReviewStatus == ReviewStatus.Unreviewed;

// 「未確認に戻す」ボタン（Completed / CompletedWithEdit のときのみ活性）
// CompletedWithEdit のとき → ResultViewModel が確認ダイアログを表示し「はい」のときに呼ぶ
// ResetToOriginal() は IsEditing を変更しないため、編集モード中に呼ぶ場合は
// 呼び出し元（ResultViewModel）が先に CancelEdit() を呼んで IsEditing を落とす
[RelayCommand(CanExecute = nameof(CanMarkUnreviewed))]
private void MarkUnreviewed()
{
    ResetToOriginal();
    ReviewStatus = ReviewStatus.Unreviewed;
}
private bool CanMarkUnreviewed() =>
    ReviewStatus == ReviewStatus.Completed ||
    ReviewStatus == ReviewStatus.CompletedWithEdit;

// Undo/Redo 用テキスト設定（CommitEdit() と同じ遷移ルールを適用）
// テキストが元の OCR 結果に戻った場合は修正完了 → 未確認に自動遷移する
public void SetTextWithoutTracking(string text)
{
    Text = text;
    EditingText = text;
    OnPropertyChanged(nameof(HasChanges));

    if (HasChanges)
        ReviewStatus = ReviewStatus.CompletedWithEdit;
    else if (ReviewStatus == ReviewStatus.CompletedWithEdit)
        ReviewStatus = ReviewStatus.Unreviewed;
}

// 元テキストへの復元（ResetAllEdits() から呼ばれる）
// テキストを元に戻すため、修正完了 → 未確認に自動遷移する
public void ResetToOriginal()
{
    Text = _originalText;
    EditingText = _originalText;
    OnPropertyChanged(nameof(HasChanges));

    if (ReviewStatus == ReviewStatus.CompletedWithEdit)
        ReviewStatus = ReviewStatus.Unreviewed;
}
```

### 6-3. JobHistoryItemViewModel への追加

`ReviewStatusKey` は `[ObservableProperty]` で管理し、`[NotifyPropertyChangedFor]` でバッジ表示文字列の連鎖通知を自動化する。  
コンストラクタで `JobHistoryItem.TextBlockReviews` を全件走査して初期集計する（§4-3 の集計ルール）。  
`_item` の `readonly` を外し、`UpdateItem()` で最新 record への差し替えを可能にする。

```csharp
// readonly を外す（SaveCurrentReviewStatus() から最新 record を差し戻すため）
private JobHistoryItem _item;

[ObservableProperty]
[NotifyPropertyChangedFor(nameof(ReviewStatusBadgeDisplay))]
private string _reviewStatusKey;

public JobHistoryItemViewModel(JobHistoryItem item)
{
    _item = item;
    _reviewStatusKey = ComputeReviewStatusKey(item.TextBlockReviews.Values);
}

private static string ComputeReviewStatusKey(IEnumerable<ReviewStatus> statuses)
{
    var list = statuses.ToList();
    if (list.Count == 0) return "unreviewed";  // TextBlock 未ロード時は未確認扱い
    return list.All(s => s != ReviewStatus.Unreviewed) ? "completed" : "unreviewed";
}

public string ReviewStatusBadgeDisplay =>
    ReviewStatusExtensions.FromKey(ReviewStatusKey).ToDisplay();

// JobStatus.ToString() が "succeeded" を返す（JobStatus.cs 確認済み）
public bool ShowReviewBadge => Status.ToString() == "succeeded";

// ResultViewModel から TextBlock ロード後に呼ぶ再集計メソッド
public void UpdateReviewStatus(IEnumerable<TextBlockViewModel> textBlocks)
    => ReviewStatusKey = ComputeReviewStatusKey(textBlocks.Select(t => t.ReviewStatus));

// 読み取り専用公開（UpdateTextBlocksForCurrentPage からの復元に使用）
public JobHistoryItem Item => _item;

// SaveCurrentReviewStatus() が保存後に呼ぶ。_item を最新の record に差し替える
// UpdateItem() は SaveCurrentReviewStatus() からのみ呼ぶ。更新対象は TextBlockReviews のみのため、
// _item 依存の表示プロパティ（FileName / StatusDisplay 等）は変化しない。追加通知は不要。
public void UpdateItem(JobHistoryItem item) => _item = item;
```

### 6-4. ResultViewModel への追加

#### TextBlock の ReviewStatus 変化を検知する仕組み

`_undoRedoService.StateChanged` や `JobHistory.CollectionChanged` と同じ購読パターンを使う。  
コンストラクタで `TextBlocks.CollectionChanged` を購読し、各 TextBlock の `PropertyChanged` を購読・解除する。  
`ObservableCollection.Clear()` は `Reset` 通知を送り `OldItems` が null になるため、`UpdateTextBlocksForCurrentPage()` の `Clear()` 前に手動で全件解除する。

```csharp
// コンストラクタに追加
TextBlocks.CollectionChanged += OnTextBlocksCollectionChanged;

// Remove 操作（1件削除）のときに自動購読・解除
private void OnTextBlocksCollectionChanged(object? sender, NotifyCollectionChangedEventArgs e)
{
    foreach (TextBlockViewModel vm in e.NewItems ?? (IList)Array.Empty<object>())
        vm.PropertyChanged += OnTextBlockPropertyChanged;
    foreach (TextBlockViewModel vm in e.OldItems ?? (IList)Array.Empty<object>())
        vm.PropertyChanged -= OnTextBlockPropertyChanged;
}

// ReviewStatus 変化時の処理（_isBatchUpdating 中はスキップ）
private void OnTextBlockPropertyChanged(object? sender, PropertyChangedEventArgs e)
{
    if (e.PropertyName != nameof(TextBlockViewModel.ReviewStatus)) return;
    if (_isBatchUpdating) return;

    SelectedHistoryItem?.UpdateReviewStatus(TextBlocks);
    OnPropertyChanged(nameof(FilteredJobHistory));
    OnPropertyChanged(nameof(IsFilteredEmpty));
    BulkCompleteUnreviewedCommand.NotifyCanExecuteChanged();
    SaveCurrentReviewStatus();
}

// UpdateTextBlocksForCurrentPage() の先頭に追加（Clear() 前に手動解除）
private void UpdateTextBlocksForCurrentPage()
{
    // Clear() は Reset 通知のため OldItems が null になる → Clear() 前に手動解除
    foreach (var tb in TextBlocks)
        tb.PropertyChanged -= OnTextBlockPropertyChanged;

    TextBlocks.Clear();
    // ...（既存処理）...
    TextEditing.SetTextBlocks(TextBlocks);
    OnPropertyChanged(nameof(FilteredTextBlocks));
    BulkCompleteUnreviewedCommand.NotifyCanExecuteChanged();  // ページ切替後に活性を更新
}

// Dispose() に追加
public override void Dispose()
{
    try
    {
        ImageDisplay.PageChanged -= OnPageChanged;
        JobHistory.CollectionChanged -= OnJobHistoryCollectionChanged;
        TextBlocks.CollectionChanged -= OnTextBlocksCollectionChanged;    // 追加
        foreach (var tb in TextBlocks)
            tb.PropertyChanged -= OnTextBlockPropertyChanged;             // 追加
    }
    finally { base.Dispose(); }
}
```

#### 永続化（SaveCurrentReviewStatus）

既存の `CancelJobUseCase`（`existing with { Status = result.Status }`）と同じパターン。  
`GetByReportId()` で最新取得 → 現在ページ分をマージ → `Update()` → `UpdateItem()` で ViewModel を最新化。

```csharp
private void SaveCurrentReviewStatus()
{
    if (SelectedHistoryItem is null) return;

    // ① 最新を Repository から取得（全ページ分の TextBlockReviews が含まれる）
    var existing = _jobHistoryRepository.GetByReportId(SelectedHistoryItem.ReportIdValue);
    if (existing is null) return;

    // ② 現在ページ分を上書きマージ（他ページ分はそのまま維持）
    var updatedReviews = new Dictionary<string, ReviewStatus>(existing.TextBlockReviews);
    foreach (var tb in TextBlocks.Where(t => t.TextBlockKey is not null))
        updatedReviews[tb.TextBlockKey!] = tb.ReviewStatus;

    // ③ with 式で差分更新して保存（CancelJobUseCase と同じパターン）
    var updated = existing with { TextBlockReviews = updatedReviews };
    _jobHistoryRepository.Update(updated);
    SelectedHistoryItem.UpdateItem(updated);  // _item を最新化（次回ページ復元に使用）
}
```

#### 一括完了（BulkCompleteUnreviewed）

`_isNormalizing` と同じパターンで `_isBatchUpdating` フラグを使い、N 件変更でも保存を1回に抑える。

```csharp
private bool _isBatchUpdating;

[RelayCommand(CanExecute = nameof(HasUnreviewed))]
private void BulkCompleteUnreviewed()
{
    // 確認ダイアログ表示後に実行
    _isBatchUpdating = true;
    try
    {
        foreach (var tb in TextBlocks.Where(t => t.ReviewStatus == ReviewStatus.Unreviewed))
            tb.ReviewStatus = ReviewStatus.Completed;
    }
    finally
    {
        _isBatchUpdating = false;
    }

    // N 件変更でも 1 回だけ処理
    SelectedHistoryItem?.UpdateReviewStatus(TextBlocks);
    OnPropertyChanged(nameof(FilteredJobHistory));
    OnPropertyChanged(nameof(IsFilteredEmpty));
    BulkCompleteUnreviewedCommand.NotifyCanExecuteChanged();
    SaveCurrentReviewStatus();
}

private bool HasUnreviewed() =>
    TextBlocks.Any(t => t.ReviewStatus == ReviewStatus.Unreviewed);
```

#### フィルター関連

既存の `string? _statusFilter`（単一選択）を `HashSet<string> _statusFilters`（複数選択）に置き換える。  
既存の `_isDateFilterVisible` / `OpenDateFilterCommand` / `CloseDateFilterCommand` は統合フィルターパネル用の `_isFilterPanelVisible` / `OpenFilterPanelCommand` / `CloseFilterPanelCommand` に統合する。  
`_isDateFilterVisible` に付いている `[NotifyCanExecuteChangedFor]`（キーショートカット群）および `CanUseKeyShortcut()` / `CanUndoViaKey()` / `CanRedoViaKey()` の参照先を `IsFilterPanelVisible` に変更する。

```csharp
[ObservableProperty]
[NotifyCanExecuteChangedFor(nameof(CloseFilterPanelCommand))]   // CloseDateFilterCommand から変更
[NotifyCanExecuteChangedFor(nameof(PreviousPageViaKeyCommand))]
[NotifyCanExecuteChangedFor(nameof(NextPageViaKeyCommand))]
[NotifyCanExecuteChangedFor(nameof(ZoomInViaKeyCommand))]
[NotifyCanExecuteChangedFor(nameof(ZoomOutViaKeyCommand))]
[NotifyCanExecuteChangedFor(nameof(FitToWindowViaKeyCommand))]
[NotifyCanExecuteChangedFor(nameof(ActualSizeViaKeyCommand))]
[NotifyCanExecuteChangedFor(nameof(UndoViaKeyCommand))]
[NotifyCanExecuteChangedFor(nameof(RedoViaKeyCommand))]
private bool _isFilterPanelVisible;

private readonly HashSet<string> _statusFilters = [];

private static readonly HashSet<string> JobStatusKeys =
    ["queued", "running", "succeeded", "failed", "canceled"];
private static readonly HashSet<string> ReviewStatusKeys =
    ["unreviewed", "completed"];

[RelayCommand]
private void OpenFilterPanel() => IsFilterPanelVisible = true;

[RelayCommand]
private void CloseFilterPanel() => IsFilterPanelVisible = false;

// チェックボックスの ON/OFF 切り替え（ジョブ・確認ステータス共用）
[RelayCommand]
private void ToggleStatusFilter(string key)
{
    if (!_statusFilters.Add(key))
        _statusFilters.Remove(key);
    OnPropertyChanged(nameof(FilteredJobHistory));
    OnPropertyChanged(nameof(IsFilteredEmpty));
    OnPropertyChanged(nameof(FilterSummary));
    OnPropertyChanged(nameof(FilterActiveCount));
}

[RelayCommand]
private void ClearAllFilters()
{
    _statusFilters.Clear();
    DateFrom = null;
    DateTo = null;
    // DateFrom/DateTo が既に null の場合 NormalizeDateRange() が通知を飛ばさないため明示
    OnPropertyChanged(nameof(FilteredJobHistory));
    OnPropertyChanged(nameof(IsFilteredEmpty));
    OnPropertyChanged(nameof(FilterSummary));
    OnPropertyChanged(nameof(FilterActiveCount));
}

// フィルター適用件数（ヘッダーバッジに表示）
public int FilterActiveCount =>
    (DateFrom.HasValue ? 1 : 0) +
    (DateTo.HasValue ? 1 : 0) +
    _statusFilters.Count;

// SearchQuery は含まない（SearchBox が常時表示のため）。空文字のとき XAML で非表示にする
// 例:「成功・失敗 かつ 未確認」「2026/04/01 〜 2026/04/30」
public string FilterSummary { get { /* 日本語文字列を生成して返す */ } }

// FilteredJobHistory のステータス判定部分（既存の StatusFilter 判定を置き換え）
if (_statusFilters.Count > 0)
{
    var jobKeys    = _statusFilters.Where(k => JobStatusKeys.Contains(k)).ToList();
    var reviewKeys = _statusFilters.Where(k => ReviewStatusKeys.Contains(k)).ToList();
    if (jobKeys.Count > 0)
        query = query.Where(j => jobKeys.Contains(j.Status.ToString()));
    if (reviewKeys.Count > 0)
        query = query.Where(j => reviewKeys.Contains(j.ReviewStatusKey));
}

// CanUseKeyShortcut() / CanUndoViaKey() / CanRedoViaKey() の参照変更（IsDateFilterVisible → IsFilterPanelVisible）
private bool CanUseKeyShortcut() => !IsFilterPanelVisible;
private bool CanUndoViaKey() => !IsFilterPanelVisible && TextEditing.UndoCommand.CanExecute(null);
private bool CanRedoViaKey() => !IsFilterPanelVisible && TextEditing.RedoCommand.CanExecute(null);

// IsFilteredEmpty の判定条件（StatusFilter 参照を _statusFilters.Count > 0 に置換）
public bool IsFilteredEmpty =>
    JobHistory.Count > 0 &&
    !FilteredJobHistory.Any() &&
    (IsDateFilterActive || !string.IsNullOrWhiteSpace(SearchQuery) || _statusFilters.Count > 0);

// NormalizeDateRange() への追記（日付変更時に FilterSummary / FilterActiveCount も更新）
private void NormalizeDateRange()
{
    // ...（既存処理）...
    OnPropertyChanged(nameof(FilteredJobHistory));
    OnPropertyChanged(nameof(IsDateFilterActive));
    OnPropertyChanged(nameof(IsFilteredEmpty));
    OnPropertyChanged(nameof(FilterSummary));       // 追加
    OnPropertyChanged(nameof(FilterActiveCount));   // 追加
}
```

## 8. 懸念点・確認事項

| 項目 | 内容 | 対応方針 |
|------|------|---------|
| **Undo / ResetAllEdits 後の ReviewStatus 同期** | Undo でテキストを元に戻したとき、または `ResetAllEdits()` で全テキストをリセットしたとき、テキストが元の OCR 結果と一致するなら `CompletedWithEdit` → `Unreviewed` に自動遷移すべき | `SetTextWithoutTracking()`（Undo/Redo 経路）と `ResetToOriginal()`（全リセット経路）に `CommitEdit()` と同じ遷移ロジックを追加して解消する（§6-2 参照） |
| **確認ダイアログの実装方法** | 「すべて完了にする」と `CompletedWithEdit` からの「未確認に戻す」で YesNo 確認ダイアログが必要。アプリ全体に既存の YesNo ダイアログパターンがなく、新規実装となる | `ResultView.xaml.cs` の code-behind で `MessageBox.Show(message, title, MessageBoxButton.YesNo)` を呼び、`MessageBoxResult.Yes` のときにコマンドを実行する（「すべて完了」→ `BulkCompleteUnreviewedCommand`、「未確認に戻す」→ `MarkUnreviewedCommand`） |
| **未ロードジョブのバッジ表示** | `Succeeded` ジョブを一度も開いていない場合、`TextBlockReviews` は空辞書のため「未確認」バッジが表示される | 許容する（開いていないジョブは確認されていないため「未確認」は正しい） |
| **フィルターパネルを開いたまま別ジョブを選択した場合** | `IsFilterPanelVisible` は `true` のまま残り、フィルターパネルが開いたまま表示が切り替わる | `OnSelectedHistoryItemChanged` で `IsFilterPanelVisible = false` にリセットする方向で実装時に判断する |
| **`SaveCurrentReviewStatus()` の書き込み単位** | TextBlock のステータス変更のたびにローカル JSON を丸ごと読み書きする。連続ページ遷移や複数操作時に書き込みが繰り返し発生する | `lock` によるスレッド安全性は確保済み。初版では許容し、性能問題が生じた場合は遅延書き込みを検討する |
| **ページ未遷移時のバッジ集計** | `UpdateReviewStatus(TextBlocks)` は現在ページの TextBlocks からのみ再集計するため、未表示ページのバッジは永続化辞書ベースで維持される | `SaveCurrentReviewStatus()` が全ページ辞書をマージして保存するため整合性は保たれる。実装時に動作を確認する |
| **フィルターパネル表示中のショートカット抑止** | `_isDateFilterVisible` → `_isFilterPanelVisible` への置き換え時に、XAML の `Escape` キーバインドと `CanUseKeyShortcut()` の参照先も合わせて変更する必要がある | Section 6 に明記済み。実装時にチェックリストとして確認する |
| **レビュー実施者の記録なし** | 現バージョンはユーザー認証基盤がないため `t_job_block_review_set` に実施者情報を持てない。マルチユーザー環境で「誰が確認したか」の監査ができない | 認証機能を追加した際に `reviewer_user_id` カラムの追加を検討する。初版では対応しない |
